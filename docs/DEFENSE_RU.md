# Fluento: подготовка к защите

## Что показать за 5–7 минут
1. Запустить START-FLUENTO.cmd. Показать четыре темы, три исходных языка и две стратегии.
2. Выбрать Russian и Sequential Review, открыть Food.
3. Сначала открываются Word cards: показать IPA, раскрыть значение apple и нажать Start practice.
4. Нажать Show hint. Объяснить: HintDecorator добавил подсказку без изменения TranslationExercise.
5. Ответить apple. Верхняя статистика изменилась через Observer; FeedbackDecorator добавил поддержку.
6. Нажать Next exercise и намеренно ошибиться на bread. Показать правильный ответ.
7. Завершить оставшиеся задания: water, milk, apple, bread, water, milk.
8. Получить 7/8 за раунд; общий процент округляется до 88%, точное значение — 87,5%.
9. All lessons → Weak Words First → Start Food. Первым будет translation-bread.
10. Открыть UML и показать все шесть паттернов, затем результаты mvn clean verify.

До демонстрации закрыть старое окно и открыть новое, чтобы статистика начиналась с нуля.
Не называть алгоритм интервальным повторением: расписания по времени нет.

## Factory Method
Проблема: создавать разные упражнения через один контракт.
Exercise — Product; TranslationExercise и MultipleChoiceExercise — Concrete Products.
ExerciseCreator — Creator; createExercise(Word) — фабричный метод.
Конкретные creators переопределяют этот метод.
DemoLessonCatalog работает с типом ExerciseCreator.
Это не просто switch с new: выбор продукта реализован через переопределение в подклассах.
Новый тип: добавить реализацию Exercise и соответствующий creator, затем подключить в catalog.
Минус: больше небольших классов.

## Builder
LessonBuilder пошагово собирает id, title и упражнения, затем build().
Lesson — неизменяемый Product; DemoLessonCatalog задаёт последовательность сборки.
Отдельный класс Director не обязателен: эту роль здесь выполняет catalog.
Проверяются пустой урок, отсутствующие поля, дубли ID.
List.copyOf защищает готовый урок от последующего изменения списка.
Отличие от Factory: Factory выбирает тип одного упражнения, Builder собирает целый урок.

## Strategy
ReviewStrategy — общий алгоритм order(); ReviewSession — Context.
Sequential сохраняет порядок; WeakWordsFirst сортирует по числу ошибок.
Контекст хранит интерфейс, а не проверяет тип стратегии.
setStrategy меняет алгоритм без изменения Exercise.
Сортировка стабильная: при равенстве ошибок остаётся прежний порядок.
Исходный список не меняется. Пропущенный ID получает ноль ошибок.
В UI стратегия выбирается перед началом раунда. Во время раунда порядок фиксирован.
Минус: вызывающая сторона должна выбрать подходящую стратегию.

## Observer
ProgressTracker — Subject; ProgressObserver — контракт; FluentoPanel,
StatisticsObserver и ConsoleProgressObserver — Concrete Observers.
recordAnswer сначала обновляет счётчики, затем публикует неизменяемый ProgressSnapshot.
subscribe/unsubscribe управляют списком подписчиков.
Повторная подписка одного объекта не даёт второго уведомления.
Сбой одного подписчика не блокирует остальных; RuntimeException передаётся обработчику.
Вложенные события стоят в очереди: подписчики видят 1 → 2, а не 2 → 1.
Копия списка позволяет отписаться в callback без ConcurrentModificationException.
Ограничение: код рассчитан на один поток EDT, а не на параллельные вызовы с сервера.
Минус: порядок/ошибки callback нужно явно проектировать; подписчиков надо освобождать, если их срок жизни короче Subject.

## Decorator
Оба декоратора реализуют Exercise и содержат другой Exercise.
HintDecorator заменяет только hint в ExerciseView, делегирует id и checkAnswer.
FeedbackDecorator делегирует id/view и дополняет feedback, сохраняя correct.
Каталог создаёт FeedbackDecorator(HintDecorator(original)).
Это композиция, а не наследование от конкретного TranslationExercise.
Одинаковый интерфейс делает обёртки пригодными для Facade и Strategy.
Минус: цепочку обёрток сложнее отлаживать, если она очень длинная.

## Facade
LessonFacade — единый API учебной сессии для UI.
Конструктор получает Lesson, ReviewStrategy и ProgressTracker.
ReviewSession вычисляет порядок. submitAnswer вызывает Exercise.checkAnswer
(включая декораторы), сохраняет результат, обновляет score и tracker.
nextExercise запрещает переход до ответа; повторный ответ запрещён.
После завершения нельзя читать новое упражнение или отвечать.
Facade не рисует кнопки и не загружает словарь — это отдельные обязанности.
Минус: нельзя превращать его в «класс для всего приложения».

## SOLID на примерах
S: отображение — LessonSessionPanel; последовательность — LessonFacade; статистика — ProgressTracker.
O: новый ReviewStrategy или ProgressObserver добавляется без правок контекста/рассылки.
L: оба Exercise и оба Decorator сохраняют id/view/checkAnswer и смысл correct.
I: ProgressObserver имеет один метод; Exercise — три небольших операции.
D: ReviewSession зависит от ReviewStrategy, tracker — от ProgressObserver.
Не утверждать, что любой конкретный класс нарушает DIP: важны точки сменяемого поведения.

## Частые вопросы
Почему record? Для простых значений с понятной структурой. Карты и списки дополнительно копируются.
Почему Map.copyOf? Неизменяемая оболочка без копирования не защищала бы от изменения исходной карты.
Почему Integer.compare? Избегает переполнения при вычитании счётчиков.
Почему ошибки не исчезают после правильного ответа? Это накопленные ошибки за окно приложения.
Что считается accuracy? correct * 100.0 / total, при total=0 — 0.
Что происходит при закрытии? Прогресс сбрасывается; сохранение на диск относится к Further work.
Разные языки имеют разную статистику? Нет: одинаковые ID объединяют статистику.
translation-water и choice-water — одно упражнение? Нет, разные ID.
Зачем тесты UI? Они проверяют соединение компонентов, чего не доказывают отдельные unit-тесты.
Что доказывает coverage? Выполнение строк/ветвей; не отсутствие всех ошибок.
Почему нельзя обещать 100 баллов? Оцениваются также личная реализация и устная защита.

## Самостоятельная репетиция
Каждая без подсказки показывает свой интерфейс, реализации, место вызова и один тест.
Затем объясняет одно изменение поведения и пишет/меняет небольшой тест сама.
Полезные реальные упражнения: Асия — проверить отписку во время уведомления;
Моля — проверить завершение сессии после неправильного последнего ответа;
al0ni — проверить новый набор слов через Builder и оба creator.
Не создавать фиктивные коммиты ради числа коммитов.

## Новые возможности для демонстрации
- Show hint / Hide hint: подсказку можно скрыть до ответа.
- Варианты ответа — кнопки; выбор можно сменить до проверки.
- I don't know: показать решение и учесть неправильную попытку без автоматического перехода.
- Restart round: начать текущий раунд заново, сохранив накопленную статистику.
- Прогресс темы: число уникальных упражнений, решённых правильно хотя бы раз, из восьми.
- Карточки: стрелки влево/вправо, пробел; Alt+P открывает практику.
- Практика: Enter — проверить/далее, Alt+H — подсказка, Alt+S — пропуск, Alt+1–4 — вариант.
Сочетания работают внутри активной панели, а не скрытой вкладки.
