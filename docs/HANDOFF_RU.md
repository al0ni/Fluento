# Как проверить и загрузить Fluento

## Сначала локально
1. Распаковать весь архив. Не запускать cmd непосредственно внутри ZIP.
2. Открыть START-FLUENTO.cmd. Нужна Java 21 или новее.
3. Для исходников открыть pom.xml в IntelliJ → JDK 21 → Reload Maven.
4. Запустить Maven verify. Ожидаемый результат указан в VERIFICATION.md.
5. Пройти сценарий из DEFENSE_RU.md.
6. Прочитать PDF; проверить данные команды и требования оформления вашего преподавателя.
В отчёте указаны Rakhimzhanova Alua, Assiya Aitbayeva, Moldir Yerzhan; группа SE-2509.
Перед отправкой проверить написание имён и дополнительные требования преподавателя к титульному листу.

## Репозиторий загружает один интегратор
Не создавайте новый репозиторий и не заменяйте папку .git.
Работайте в вашей существующей копии al0ni/Fluento.
Сначала git status: если есть свои несохранённые изменения, сохраните их отдельно.
Далее при чистой рабочей копии:

```powershell
git fetch origin
git switch -c integration/sdp-final-2026-11-15 origin/main
git merge --no-ff origin/feature/lesson-session
git merge --no-ff origin/feature/progress-system
```

Эти команды сохраняют исходную историю Моли и Асии. Это инструкция для вас:
в рамках подготовки архива удалённые ветки не сливались.
Если Git сообщает конфликт или ветки изменились, не применять force и не выбирать всё вслепую.
Сначала сравнить изменения с PROVENANCE.md.

После двух локальных слияний:
- Скопировать из архива содержимое src в src вашего репозитория с заменой соответствующих файлов.
- Скопировать pom.xml, README.md, START-FLUENTO.cmd.
- Скопировать docs с заменой документов; просмотреть изменения через git diff.
- Не копировать .git, target, .idea. Папка dist нужна для запуска готового архива,
  но не нужна для обычного исходного коммита (она игнорируется).
- Собрать mvn clean verify.
- Проверить запуск java -jar target/fluento-1.0-SNAPSHOT.jar.

```powershell
git diff --stat
git diff --check
git add src pom.xml README.md START-FLUENTO.cmd docs
git commit -m "Integrate six patterns and add final verification"
git push -u origin integration/sdp-final-2026-11-15
```

Создать PR из integration/sdp-final-2026-11-15 в main.
В описании отметить исходные ветки, интеграционные изменения, использование ИИ и результаты тестов.
Посмотреть diff и дать команде проверить. Не делать force-push и не менять авторов старых коммитов.
После проверки PR можно слить обычным merge, сохраняя историю.

## Что делают Асия и Моля
Не нужно каждой загружать один и тот же готовый проект под видом собственной разработки.
Обе проверяют свои классы и интеграционные изменения, запускают тесты и репетируют объяснение.
Реальные дополнительные исправления или тесты оформляют собственными коммитами.
Сам факт загрузки не заменяет требование индивидуальной реализации двух паттернов.

## Что сдавать
- PDF-отчёт docs/Final_Report.pdf.
- ZIP исходников; архив доставки содержит также готовый JAR для удобного запуска.
- Если нужны отдельные архивы строго по формату Moodle, упаковать src, pom.xml, README.md и docs.
- Перед отправкой проверить личные данные на титульном листе и ещё раз открыть PDF.

## Важно о запуске после собственных изменений
START-FLUENTO.cmd запускает dist/fluento.jar из подготовленного архива.
После изменения исходников используйте свежий target/fluento-1.0-SNAPSHOT.jar
или скопируйте его в dist/fluento.jar. Иначе можно случайно показать старую сборку.
